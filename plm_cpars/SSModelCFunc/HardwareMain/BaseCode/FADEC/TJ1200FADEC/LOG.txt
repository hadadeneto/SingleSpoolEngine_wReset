08/05/2023
- Adição de uma linha de comando na função de salvamento do arquivo de telemetria interna.
	- No último voo (Formosa II), o FADEC não gravou os últimos segundos da telemetria.
		- Isso aconteceu pois a função ofstream() grava em um buffer, e somente depois de encher esse buffer ele salva o arquivo.
- Para solucionar isso, duas funções serão utilizadas:
	- flush(): salva o buffer de ofstream imediatamente no arquivo.
		- Porém, ainda é necessário fazer com que o sistema operacional grave o arquivo efetivamente na memória flash.
	- fsync(): função otimizada de sync(), que salva o arquivo passado como parâmetro imediatamente na memória flash.
- IMPORTANTE:
	- A função flush() consegue ser executada rapidamente, com os maiores tempos registrados abaixo de 20us.
	- Por outro lado, a função fsync() chegou a registrar quase 250ms para sua execução (ainda bem abaixo dos 600ms de sync()).
		- Portanto será necessário criar uma thread somente para a função fsync().
- Threads criadas e programa testado com sucesso.
	- Escorregamento máximo registrado após um teste de 3h seguidas: 244ms.
	- Deu uma piorada no escorregamento.
		- Obs: esse valor foi obtido utilizando o CAN-Monitor 3000 TM, programa que eu desenvolvi baseado no CAN-Monitor 3000.
			- A interface CAN foi com o Zubax Babel.
		- Há a possibilidade desse monitor ser mais lento que o da National, então o escorregamento na rede do POC pode ser menor.
	- De qualquer forma, o valor está dentro das tolerâncias.
- Melhoria para minimizar o escorregamento:
	- Limitei o salvamento do arquivo em uma vez a cada 1 segundo.
	- Para isso utilizarei if ( upTime_ms >= (last_saveTelemetryFile_ms + FADEC_SAVE_TELEMETRY_FILE_PERIOD_MS) )
	- Testes serão realizados para ver se o escorregamento melhorou.
