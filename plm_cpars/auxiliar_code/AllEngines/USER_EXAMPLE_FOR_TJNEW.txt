
SIMPLIFIED STEPS for TJNEW engine

In SSModelCFunc folder:
    
    1 - Create file TJNEWFADEC.c, from an existing XXXFADEC.c file

    2 - Inside the created file, replace XXX name for TJNEW name in any line - this file will be used as basis for update

    3 - Create the folder HardwareMain\BaseCode\FADEC\TJNEWFADEC containing the hardware FADEC files to be modified. This can be done by copying and renaming
        a previous XXXFADEC folder already containing the files to be used as basis and modified
    4 - Create the folder HardwareMain\Generated\FADEC\TJNEWFADEC. This folder can be left empty, since it will receive the modified FADEC file for real hardware

    5 - Create the folder TJNEW\FADEC_Constants_H

    6 - Inside the folder above, place the file ConstantsTJNEW.h containing the values of the engine constants. This file can be generated based on previous engine files

In auxiliarcode\AllEngines

    1 - Create the folder Engines\TJNEW_Project (the _Project part is optional. However, this folder contains the name of the project, not necessarely the final engine name)

    2 - In the folder above, place the EngineData.m file, the TMATSData folder generated in TMATS software, the SubIdleMtx.mat and WindMillMtx.mat. If one wishes to use the same
        PI constants for sub idle as another engine, copy also the file PIsh.mat. 
        NOTE:   The matrices of SubIdleMtx.mat and WindMillMtx.mat are generated externally and must have the same size as the matrices generated by TMATS, i.e., same 
                number values of linearization Mach Numbers and Altitudes (in the case of SubIdleMtx.mat)
        NOTE:   The EngineData.m must contain the data corresponding to TJNEW engine, such as engine name, what needs to be generated during execution of DesCode and controller 
                design characteristics for both sub-idle and above-idle regimes.

    3 - Edit SetEngineList.m, adding the corresponding names of the new engine project (TJNEW_Project), version of static deck simulator (typically 1.00 for the first time)
        and TJNEW (engine name) in the corresponding lists. It is recommended that the engine is included in every list for avoiding future problems in software execution

Runing DesCode:

    1 - In DesCode, set EngFoldName to TJNEW_Project or the chosen name for the project folder

    2 - Go to auxiliarcode\AllEngines, and in MATLAB command window, type DesCode

    3 - For setting a SIL simulation, type the command SetSIL

Running SIL simulation

    1 - Set the MATLAB current path to the folder plmc_pars\SSModelCFunc

    2 - Make sure all changes in SSModelLoop.c has been done for adding TJNEW engine to the simulation

    3 - Create the file LoadTJNEW for correct map plotting, containing the map constants calculated in TMATS

    4 - In RunModel, add TJNEW engine - the engine number must match the engine number in SSModelLoop.c - and elaborate and engine mission to be run, based on other engine missions

    5 - Go to the path of plmc_pars folder

    6 - Run CompileCSFun command in MATLAB window

    7 - Finally, run RunModel command in MATLAB window

Generating Code Pack

    1 - Set the path to auxiliarcode\AllEngines folder

    2 - Run the command CodePacking in MATLAB window
        NOTE: The generated code will be based on the code present in SSModelCFunc folder. Make sure its working properly
        NOTE: The code pack contains the HIL code, the FADEC code for hardware of TJNEW engine, TMATS FADEC code of TJNEW engine

Generating Static simulation deck

    1 - Set the path to auxiliarcode\AllEngines folder

    2 - Run the command StaticSimGen in MATLAB window. The static simulation code will be in CodePack\StaticSim

Running FADEC code in TMATS

    1 - Copy the folder TJNEWFADEC from CodePack\FADEC_TMATS to AllEngines\Engines\TJNEW\DynamicModel of TMATS simulator

    2 - Edit the CompileCSFun.m code inside TJNEW\DynamicModel adding the following code piece:



%--------------------------
%COMPILATION OF TJ1200FADEC
%--------------------------

%Adds path of current FADEC to be compiled
FADECFolder = 'TJ300RFADEC';

CompiledFileName = 'FADEC_TJ300R.mexw64';


%
CurPath = pwd;
%Goes inside FADEC folder for compilation
cd(FADECFolder);
%
SourceFilePath = [pwd filesep CompiledFileName];
%Compilation of FADEC
MATLAB_FADEC_TJ300R_Compile;
%
cd(CurPath)
%
if isfile(CompiledFileName)
    delete(CompiledFileName)
end
%
copyfile(SourceFilePath,CurPath,'f');



    3 - In TJNEW\DynamicModel, run CompileCSFun.m

    4 - Make sure the S-Function name inside the user block containing the FADEC is TJNEWFADEC and that the corresponding inputs and ouptus 
        are correctly set

    5 - Finally, run a dynamic simulaton with the FADEC code

ADDITIONAL AUTOMATION

Updating ConstantsTJNEW.h from ConstantsBase.h

    1 - Make any required updates in SSModelCFunc\ConstantsHBase\ConstantsBase.h 
        NOTE: The updates must be consistent, since they will be made in 
              all ConstantsXXX.h files for all engines.

    2 - In the file plm_cpars\auxiliar_code\AllEngines\EngConstUpdate.m, 
        set the desired value of COMMENTS_FROM_BASE, either 0, for keeping 
        the comments after each constant from original file, or 1, for 
        replacing the comments for the ones in ConstantsBase.h. if COMMENTS_FROM_BASE
        is set to 1, the texts <Control> must be present in the constant's comments
        written besides its value
    
    3 - Also in EngConstUpdate.m,set the desired value for AUTO_UPDT_CONTCONSTPARS, 
        1 for performing automatic update of ContConstPars.m and 0 for not performing
        it. When automatic update is requested, the following constant name rule is
        followed:
        XXX_CONSTANT_NAME -> ConstantName (C name)
        XXX_CONSTANTNAME  -> Constantname (C name)

    4 - Run EngConstUpdate.m by either opening the file and pressing run 
        inside the opened file or by typing EngConstUpdate in the MATLAB
        command window. All original constants .h files will be backed up
        in the plm_cpars\Backups\ConstantsH_Date... folder.

    5 - If the ContConstPars.m has not been updated automatically, it must be done
        manually after step 4. 

    6 - In the file Control_Types.h, add the new constant, using the C name, in 
        the struct ControllerConstants

Updating software automatically:
  
 - Update constans in base                                                                                              (in folder auxiliar_code/AllEngines)
 - Run EngContUpdate                                                                                                    (in folder auxiliar_code/AllEngines) 
 - Make shure the new constant is added in Control_Types.h with its chosen C name 
 - Update all C codes using AllCodeUpdt command (necessary only when constants are changed)                             (in folder auxiliar_code/AllEngines)  
 - Update code in SSModelLoop.c as desired                                                                              (in folder plm_cpars) 
 - Compile and run for validation with HIL = 0 in RunModel                                                              (in folder plm_cpars)
 - Update all FADECs, including the lite, with the command FADECMLUpdt                                                  (in folder auxiliar_code/AllEngines)
 - Compile and run for validation with HIL = 1 in RunModel                                                              (in folder plm_cpars)
 - Generate code packing using CodePacking command                                                                      (in folder auxiliar_code/AllEngines)
